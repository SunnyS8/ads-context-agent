Ниже план создания **агента автоматизации контекстной рекламы в OpenCode**. Он будет разрабатывать и запускать код для получения статистики, расчета KPI, формирования рекомендаций и, после подтверждения, изменения ставок или статусов кампаний.

Реализация (Рев. 2, утверждена): Python 3.12 + FastAPI (бэкенд), Next.js 14 (фронтенд), aiogram (Telegram-бот). Платформы: **Яндекс.Директ через eLama API (основной прослой)** и **VK Ads (TARGETING)**. Полный цикл: управление кампаниями, анализ данных, генерация креативов через LLM.

Важно: OpenCode сам по себе не является рекламной платформой. Он выступает как AI-агент для создания и сопровождения проекта. Для управления рекламой потребуется API Яндекс Директа (через eLama как основной прослой) и API VK Ads (TARGETING). [help.elama](https://help.elama.ru/article/82321)

## 1. Цель первого релиза

Начать не с полностью автономного управления рекламой, а с безопасного MVP:

1. Получать статистику рекламных кампаний.
2. Сохранять данные в PostgreSQL или Google Sheets.
3. Рассчитывать расходы, клики, заявки, CPL, CPA и ДРР.
4. Находить отклонения от KPI.
5. Отправлять рекомендации в Telegram.
6. Изменять ставки только после подтверждения пользователя.
7. Вести журнал всех действий агента.

Целевая схема:

```text
eLama API (основной прослой для Яндекс.Директ)        VK Ads (TARGETING)
          ↓                                                     ↓
       PlatformAdapter (единый интерфейс ядра)                   ↓
          ↓--------------------------------------------> API-клиенты
          ↓
    База статистики (PostgreSQL + Redis)
          ↓
    Модуль расчетов KPI
          ↓
    AI-анализ и рекомендации + Генерация креативов
          ↓
  Telegram Bot / Web-панель (Next.js)
          ↓
  Изменение ставок после подтверждения
```

## 2. Роль OpenCode

В OpenCode стоит создать несколько специализированных агентов, а не одного большого агента:

| Агент | Задача |
|---|---|
| `architect` | Проектирует структуру и технические решения |
| `developer` | Пишет Python-код и интеграции |
| `tester` | Создает тесты и проверяет ошибки |
| `analyst` | Анализирует статистику и формирует рекомендации |
| `reviewer` | Проверяет безопасность и изменения перед применением |

OpenCode поддерживает пользовательские агенты, которые можно создавать в `.opencode/agents/`; для каждого агента задаются отдельные инструкции, модель и права доступа.  Проектные правила можно хранить в `AGENTS.md`, а общие настройки и MCP — в `opencode.json` или `opencode.jsonc`. [opencode](https://opencode.ai/docs/agents/)

## 4. Настройка OpenCode

В корне проекта создайте `AGENTS.md`:

```markdown
# Контекст проекта

Проект автоматизирует анализ и управление контекстной рекламой.

## Правила безопасности

- Никогда не выполнять изменения в рекламных кампаниях без явного подтверждения.
- Не хранить API-ключи в Git.
- Использовать только переменные окружения из файла .env.
- Все изменения ставок записывать в audit_log.
- Для тестов использовать mock API.
- При недостатке статистики выдавать рекомендацию, но не менять ставки.
- Не изменять дневной бюджет автоматически.
- Перед применением изменений показывать пользователю кампанию, старую ставку, новую ставку и причину.

## Технологии

- Python 3.12
- FastAPI + Uvicorn
- PostgreSQL 15 + Redis 7
- SQLAlchemy 2.0 (async) + Alembic
- Pydantic v2
- httpx (HTTP-клиент)
- APScheduler (планировщик)
- aiogram 3.x (Telegram-бот)
- OpenAI API (генерация креативов)
- Next.js 14 (App Router, TypeScript, Tailwind, Recharts)
- pytest + httpx (тесты)
- Docker Compose

## Платформы

- **eLama** — основной API-прослой для Яндекс.Директ (управление кампаниями, Aggregated Reports, оплата). Авторизация: API-токен.
- **VK Ads (TARGETING)** — управление кампаниями VK, статистика, аудитории (lookalike, ретаргетинг). Авторизация: access_token.
- Общий интерфейс `PlatformAdapter`, адаптеры: `ElamaAdapter`, `VKAdsAdapter`, `MockAdsProvider`.

## Стиль

- Небольшие функции.
- Типизация Python.
- Обработка ошибок API.
- Тесты для бизнес-логики.
- Документация каждого публичного метода.
```

## 5. Этапы разработки

### Этап 1. Описание требований

В `README.md` зафиксировать:

- какие рекламные системы используются;
- какие кампании анализируются;
- источник заявок;
- список целей Метрики;
- целевой CPL или ДРР;
- допустимое изменение ставки;
- частота анализа;
- кто подтверждает изменения.

Пример KPI:

```text
Целевой CPL: 1 500 рублей
Минимум конверсий для решения: 5
Период анализа: последние 7 дней
Максимальное изменение ставки: 15%
Максимальная ставка: 250 рублей
Автоизменение бюджета: запрещено
```

### Этап 2. Получение данных

Сначала реализовать режим только для чтения:

- список кампаний;
- статус кампании;
- объявления;
- ключевые фразы;
- показы;
- клики;
- расход;
- конверсии;
- стоимость конверсии;
- доход, если передается ecommerce-выручка.

Для eLama сначала нужно проверить наличие подходящего API или готового коннектора. Если прямого API eLama для нужной операции нет, архитектуру лучше строить через API Яндекс Директа, а eLama оставить как интерфейс управления и оплаты. Для обмена данными между eLama и Яндекс Директом существуют готовые коннекторы, но их возможности нужно отдельно проверить перед разработкой. [help.elama](https://help.elama.ru/article/82321)

### Этап 3. Слой хранения

Создать таблицы:

```text
campaigns
- id
- external_id
- name
- status
- daily_budget
- target_cpl

statistics
- campaign_id
- date
- impressions
- clicks
- spend
- conversions
- revenue
- cpc
- cpa
- roas

recommendations
- id
- campaign_id
- action
- old_value
- new_value
- reason
- status
- created_at

audit_log
- id
- user
- action
- payload
- result
- created_at
```

### Этап 4. Расчет показателей

Агент должен рассчитывать:

\[
CTR = \frac{Клики}{Показы} \times 100\%
\]

\[
CPC = \frac{Расход}{Клики}
\]

\[
CPA = \frac{Расход}{Конверсии}
\]

\[
ДРР = \frac{Расход}{Доход} \times 100\%
\]

Если конверсий нет, система не должна автоматически делать вывод, что кампания неэффективна. Она должна учитывать период обучения, задержку конверсий и достаточность объема данных.

### Этап 5. Правила рекомендаций

Пример логики:

```text
Если кликов меньше 30:
    недостаточно данных

Если расходов больше 2 × целевого CPL
и конверсий нет:
    рекомендация снизить ставку или приостановить проверку

Если CPA ниже целевого на 20%:
    рекомендация увеличить ставку на 10%

Если CPA выше целевого на 30%:
    рекомендация снизить ставку на 10%

Если расход растет, а конверсии падают:
    отправить предупреждение

Если кампания не имеет статистики:
    ничего не менять
```

На первом этапе агент только формирует рекомендацию:

```json
{
  "campaign_id": "123456",
  "action": "decrease_bid",
  "old_bid": 120,
  "new_bid": 108,
  "reason": "CPA выше целевого на 34%",
  "requires_approval": true
}
```

### Этап 6. Telegram-подтверждение

Сообщение пользователю должно выглядеть так:

```text
Кампания: Ремонт квартир — Поиск
Текущая ставка: 120 ₽
Предлагаемая ставка: 108 ₽
CPA: 2 010 ₽
Целевой CPA: 1 500 ₽
Отклонение: +34%

Применить изменение?
[Да] [Нет]
```

Только после нажатия «Да» агент вызывает API изменения ставки. Любое изменение должно записываться в `audit_log`.

### Этап 7. Планировщик

Запускать задачи по расписанию:

```text
08:00 — загрузка статистики
08:15 — расчет KPI
08:30 — поиск аномалий
08:35 — формирование рекомендаций
09:00 — отправка отчета
18:00 — повторная проверка
```

Для MVP можно использовать `APScheduler`, а в дальнейшем — Celery или встроенный планировщик n8n.

## 6. Промпт для OpenCode

Первый запрос агенту `architect`:

```text
Ты архитектор проекта context-ads-agent.

Нужно спроектировать MVP агента автоматизации контекстной рекламы.

Ограничения:
- Python 3.12;
- API-слой должен быть заменяемым;
- первый режим — только чтение статистики;
- изменения ставок запрещены без подтверждения;
- API-ключи только через .env;
- все действия записываются в audit_log;
- необходимы mock-клиенты для тестов;
- база данных PostgreSQL;
- запуск через Docker Compose.

Подготовь:
1. архитектуру модулей;
2. модели данных;
3. последовательность обработки статистики;
4. интерфейсы API-клиентов;
5. правила безопасности;
6. план разработки по небольшим задачам;
7. критерии приемки MVP.

Не пиши код до утверждения архитектуры.
```

Затем запрос агенту `developer`:

```text
Реализуй задачу из утвержденного плана: создай интерфейс AdsProvider и MockAdsProvider.

Требования:
- типизация;
- асинхронные методы;
- получение кампаний;
- получение статистики;
- получение текущей ставки;
- изменение ставки пока запрещено в реальном клиенте;
- unit-тесты;
- обработка ошибок;
- документация README.

Перед изменением файлов перечисли план действий.
После реализации запусти тесты и покажи измененные файлы.
```

## 7. Критерии готовности MVP

MVP можно считать готовым, если:

- агент получает статистику минимум за 7 дней;
- данные сохраняются без дублирования;
- KPI рассчитываются тестами;
- отчет формируется автоматически;
- рекомендации содержат причину и числовые значения;
- секреты не попадают в Git;
- API-ошибки корректно обрабатываются;
- изменения ставок заблокированы по умолчанию;
- действия записываются в журнал;
- есть режим `dry-run`;
- проект запускается одной командой через Docker Compose.

## 8. Порядок запуска

На Фазе 0 структура уже создана. Последующие этапы:

```powershell
# 1. Инфраструктура (PostgreSQL + Redis)
docker compose up -d

# 2. Бэкенд
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
alembic upgrade head
uvicorn src.main:app --reload

# 3. Фронтенд
cd frontend
npm install
npm run dev

# 4. Telegram-бот
cd bot
pip install -r requirements.txt
python bot.py
```

Дальше порядок работы:

```text
1. /init
2. Выбрать architect
3. Утвердить архитектуру
4. Выбрать developer
5. Реализовать mock-интеграцию
6. Выбрать tester
7. Запустить тесты
8. Подключить eLama API в режиме чтения
9. Подключить VK Ads API в режиме чтения
10. Подключить Telegram
11. Добавить dry-run
12. Только после тестирования разрешить изменение ставок
```

OpenCode поддерживает запуск в терминале, IDE и через другие интерфейсы; его можно расширять MCP-серверами, если потребуется подключить базы данных, файловую систему или внешние инструменты. [opencode](https://opencode.ai/docs/config/)

## Практическая рекомендация

Для вашей задачи я бы выбрал трехэтапный вариант:

1. **MVP:** статистика и отчеты без изменения рекламы.
2. **Pilot:** рекомендации и подтверждение ставок через Telegram.
3. **Production:** ограниченное автоматическое изменение ставок по правилам.

Не рекомендую начинать с агента, который самостоятельно меняет бюджеты, отключает кампании или запускает новые объявления. Сначала нужно проверить качество целей Метрики, корректность данных CRM и поведение правил на исторической статистике.
